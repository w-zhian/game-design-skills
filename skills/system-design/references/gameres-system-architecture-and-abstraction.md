# GameRes 系统架构分层与体验抽象方法

蒸馏自 GameRes 游戏策划版块高分老文（评分依据见
`skills/article-curation/references/curation-criteria.md`），用于核心系统
架构设计与系统玩法的体验抽象/优化。

## 1. 核心游戏系统五层架构

来源：《十全干货：核心游戏系统架构设计》（Finney，2016，
https://www.gameres.com/forum/t/677342 ，43k 浏览）

方法：用分层结构（Layered structure）解构复杂系统——每层职责单一、单向
依赖，便于多人分工，并为后期"hack"留出余地。按执行顺序自上而下：

1. **世界信息层**：知识池（Knowledge Pool，世界状态数据存储，key-value
   黑板式）+ 感知器（Sensor，全局感知如势力图 / 个体感知如视野听力），
   为下层预备数据。
2. **决策层（做什么）**：AI 状态机/行为树只产出"请求"（Request），不掺
   寻路/动画等下层逻辑；在此控制决策频率（远处单位降频）；玩家输入本质
   也是一种决策，可与 AI 共用一套行为树。
3. **请求层（防火墙）**：双缓冲结构（前端请求=执行中，后端请求=候选），
   条件满足才 Flip；打断/优先级规则（如技能打断普攻）集中在此层，用
   优先级表 + 规则判定实现。上下层因此互不关心"决策能否被执行"。
4. **行为层（怎么做）**：行为树/状态机执行胜出的请求——寻路、动画选择、
   多行为组合（集气→释放）都在此层；产出运动信息（位移/旋转/缩放 + 动画）。
5. **运动层**：处理"动画跟随物理"与"root motion（物理跟随动画）"的混合
   与修正，输出最终空间表现。

网络同步的分层映射：同步点在第 2 层 = 同步输入；第 3 层 = 同步命令；
第 4/5 层 = 同步状态——越往下数据量越大但失同步风险越小。

策划视角的应用：给程序提战斗/AI 需求时，按"感知→决策→规则打断→行为→
表现"拆解描述，能显著降低沟通与返工成本。

## 2. 系统策划的体验抽象方法论

来源：《什么是系统策划？浅谈对系统策划的理解（万字长文）》（chinakille，
2014，https://www.gameres.com/forum/t/250890 ，72k 浏览）

系统策划职责一句话：**抽象、优化游戏体验，实现盈利**。

### 2.1 体验抽象：行为模拟 + 数学问题

游戏 = 用【行为模拟】解决【数学问题】。抽象游戏体验 = 选取现实/想象中的
行为模拟，抽取关键流程，艺术化夸张后用来解决数学问题。

好体验的五特性检验：**可学习、可重复、可组合、可变化、可对比**。

- 可学习：贴合生活经验，学习成本最小化、反馈细腻。
- 可组合：少量简单操作组合出大量变化（"我太聪明了"的优越感）。
- 可变化：变化是乐趣源泉，变化量 ≈ 生命周期。
- 可对比：结果数据与过去/他人对比产生成长感与互动。

经典抽象案例：傲剑经脉（简单直观）、魔兽冲锋、傲视天地九宫格战斗
（阵法概念清晰化）、传奇随机传送卷（把跑路麻烦变成乐趣）、神仙道竞技场。

### 2.2 六种抽象方法

1. 经典游戏山寨法（注意著作权，适合内嵌小游戏）。
2. 经典游戏改进法（针对经典弱点创新，适合大型游戏）。
3. 借鉴法（从游戏外领域借鉴玩法模式，如餐馆经营/模拟摄影）。
4. 文学法（从名著/小说还原玩法，如解谜、恐怖、DND）。
5. 组合法（强制融合已知玩法：动作+射击、塔防+卡牌=植物大战僵尸）——
   作者最常用。
6. 独创法（最难成功但最酷，如合金装备的潜行体系）。

### 2.3 优化三板斧

1. **搜集反馈**：主动反馈（降低提交成本+适度奖励）；被动反馈（行为数据，
   系统定稿后第一件事 = 定义能证明"系统达到预期体验"的埋点，如副本时长、
   首次通关战力）。
2. **反馈分析**：不一味顺从玩家（迷失方向），也不一味拒绝（个性伤害用户）；
   结论必须有数据/行为证据，否则是主观臆断。
3. **修改方案**：多提供几种方案；本质是重新走一遍"抽象体验"流程。

装备强化系统演化史（体验优化样本）：传奇（高失败率+爆装备，参与度低）→
奇迹（失败不掉装，+7 发光）→ 征途（道具易得，+7 分段保护）→ 傲视天地
（几乎不失败、失败返还、数值平滑）→ 卡牌（资源循环好但追求单一）。
规律：降难度、提参与度、强化满足感、优化资源循环、控制兴奋点。

### 2.4 付费目标的自然建立

付费目标要靠战斗表现/界面细节让玩家**自己发现**养成点：武器击打飘字 ⇒
"换武器会更厉害"；九宫格里武将稀少 ⇒ "多上几个会更厉害"。要在战斗界面
任何地方都看不到某养成点（如坐骑），玩家就无法自然建立该付费认知。
原则：太直白显得坑，太委婉没人发现，靠表现引导最自然。

## 使用建议

- 新系统立项：先过五特性检验（可学习/可重复/可组合/可变化/可对比），
  缺一补一。
- 与程序对齐核心玩法实现时，用五层架构语言描述需求与规则打断优先级。
- 老系统优化：按三板斧走，先补埋点再谈方案；参考强化系统演化史选择
  优化方向。
