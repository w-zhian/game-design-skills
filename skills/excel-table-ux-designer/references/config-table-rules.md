# 配置表 / 工程表专用规则

> 适用对象：会被脚本读取并导出成程序数据的表。
> **第一原则：排版不得破坏契约。** 表改了但游戏里没生效，比表丑严重一百倍。

---

## 1. Luban 的硬约束（已验证）

来源：`https://www.datable.cn/docs/excel/basics` 等 Luban 官方文档（2026-11 核对）。

### 1.1 sheet 与表头识别

| 规则 | 判定 | 违反后果 |
|---|---|---|
| A1 必须以 `##` / `##var` 开头 | 是 → 该 sheet 是数据表 | **整表被跳过**，表改了但不生效 |
| A1 不是 `##` | 是 → 该 sheet 是说明页/字典页 | 不导出，但可给人读 |
| 必须存在 `##var`（字段名）行 | 是 | 缺 → 字段全错位或导出失败 |
| 必须存在 `##type`（类型）行 | 是 | 缺 → 类型推断失败 |
| `##group`（分端 c/s）行 | 可选 | 缺 → 所有列视为双端共用 |
| `##comment`（注释）行 | 可选 | 缺 → 无字段说明 |

**行顺序可调**，但类型名禁止汉化（`int` 不能写成「整数」）。
**行首是 `##` 的行 = 注释行**，整行不导出——这是「某行怎么改都不生效」的头号原因。

### 1.2 注释列 vs 注释行（最容易搞混）

| 写法 | 含义 |
|---|---|
| 列名以 `#` 开头 | 该**列**是注释列，不导出 |
| 列名为空 | 该**列**是注释列，不导出 |
| 某行第一格是 `##` | 该**行**是注释行，不导出 |

**反模式**：备注列没加 `#` → 被当成正式列，填了值直接进游戏。

### 1.3 合并单元格：不禁止，但要分清两类

Luban **允许**合并单元格，用于表达「一个字段占多列」的结构（如 `list` / `bean` 的子字段）。

| 类型 | 特征 | 处理 |
|---|---|---|
| **结构性合并** | 有下级 `##var` 子字段行，列数与 bean/容器实际占用列数一致 | **保护，不要动** |
| **破坏性合并** | 合并了但列数不匹配，或把 `list` 中间留空 | 必须修 |

判断方法：看合并区上方是否有对应的子字段标记行。有 → 结构性。

**真正会被工具报错的情况**：合并区列数与 bean/容器实际占用列数不一致；
把字段名在每一列重复填写（与 Excel 合并语义冲突）；
`list` 中间留空（元素错位）；map 只写 key 没写 value。

### 1.4 校验器写在表头（「排版即 schema」）

Luban 支持把校验规则写进 `##type` 行，生成期硬校验：

| 写法 | 作用 |
|---|---|
| `#range=0-100` | 数值范围 |
| `#ref=ItemConfig` | 引用另一张表的主键 |
| `#set=1,2,3` | 枚举集合 |
| `[必填]` / `!` | 非空校验 |

**这就是配置表排版的最高形态**：表头既是文档又是校验规则，改了类型就自动生效。

### 1.5 其他硬约束

- `datetime` 留空会解析失败（不是"默认值"，是报错）
- 主键必须唯一（map 表），引用到的 id 必须在目标表真实存在
- 字段名必须 ASCII、合法变量名、非重复
- 文件必须在 `__tables__` 注册，只建 xlsx 不注册 → 数据不会被收集
- 数值列不要用逗号做分隔符（逗号是电子表格的大数分隔符，会被误解析）

### 1.6 其他工具链的共同约束

tabtoy / xlsx-exporter / XlsToJson 的共识：ASCII 字段名、独立类型行、主键唯一、枚举专表、sheet 名必须字母数字。
→ 这些是跨工具链的**行业惯例底线**，不依赖具体工具成立。

## 2. 配置表排版诊断清单

按优先级排列。前 4 项是「会出事」，后 4 项是「会难受」。

| 优先级 | 检查项 | 判据 | 改法 |
|---|---|---|---|
| P0 | A1 是否 `##` 开头 | 否 → 整表被跳过 | 补 `##`；确认工具链后再改 |
| P0 | `##var` / `##type` 行是否存在 | 缺任一 | 补齐标记行 |
| P0 | 类型名是否被汉化 | `整数` 而非 `int` | 改回英文 |
| P0 | 主键列是否重复 | 有重复值 | 条件格式标红 + 人工确认哪个对 |
| P1 | 注释列是否加 `#` | 备注列无 `#` | 加 `#`，否则会进游戏 |
| P1 | 列宽是否够 | 字段名/内容被截断 | 按内容设宽（不影响导出） |
| P1 | 是否冻结表头与主键列 | 未冻结 | 冻结到 `B{数据首行}` |
| P2 | 分端列是否有可视化区分 | `c`/`s` 列无颜色区别 | 加色但**必须配图例**，见 §3 |
| P2 | 是否有数据验证 | 无下拉/范围限制 | 叠加 Excel 数据验证做录入期提示 |

## 3. 配置表能不能加颜色？（边界明确）

**可以，但有严格边界。**

| 允许 | 禁止 |
|---|---|
| 给 `##group` 行的 c/s/空列着色 + 配图例 | 给数据格加装饰性底色 |
| 给人工填写区 vs 程序生成区做颜色区分 | 用颜色表达「这个值好不好」这类主观判断 |
| 给草稿行/tag 行做浅色标记 | 无图例的任意上色 |
| 条件格式标错（重复/空值/越界） | 静态色覆盖条件格式色（静态色是快照，会骗人） |

**根本原因**：策划常用颜色承载「这一列是客户端的」「这行还没定稿」这类**语义**。
AI 一加装饰色就会覆盖这些语义——用户的视觉记忆被破坏，比不加色更糟。

`beautify.py --mode config` 因此**不加任何表头底色**，只加粗 + 加下边框。

## 4. 列顺序与宽窄表

### 4.1 列顺序（行业惯例，非硬约束）

```
[id] → [基础属性: 名称/图标/品质] → [玩法属性: 数值/成长] → [表现: 特效/音效] → [#备注]
```

- ID 永远第一列，作为冻结锚点
- 备注列永远最后，且加 `#`
- 「程序必读」的列靠左，「策划常改」的列靠右 —— 减少横向滚动

### 4.2 宽表 vs 窄表

| 形态 | 优点 | 缺点 | 适合 |
|---|---|---|---|
| 宽表（一表多列） | 一眼看到全部字段，改一处不用跳表 | >150 列后失控，滚动易丢失上下文 | 单实体字段 <60 |
| 窄表（拆多表 + ID 关联） | 每表职责单一，协作冲突少 | 改一个实体要跳多表 | 字段 >60 或多人协作 |

**判据**：一屏（1920px ≈ 40 列）放不下且需要频繁横向比对 → 考虑拆表。
但拆表会让 `#ref` 引用变多，不要为了好看拆。

### 4.3 按模块分文件 vs 单文件多 sheet

| 方式 | 适合 | 风险 |
|---|---|---|
| 分文件 | 多人协作、模块边界清晰 | 跨文件引用易断 |
| 单文件多 sheet | 强相关的表（角色/装备/宝物） | 文件体积大、冲突集中 |

惯例：**策划文档按模块分（战斗/关卡/系统/数值），配置表按 3 模块分（活动/战斗/系统）**，
加 `_meta` 与 `version.txt`。

## 5. 让「程序改过的字段」一眼可见

这是配置表独有的 UX 问题：策划改了字段，程序生成器又覆盖了，谁的版本是对的？

| 手段 | 做法 |
|---|---|
| 区域着色 + 图例 | 人工维护区浅黄、程序生成区浅灰，在表头上方放图例行 |
| 批注 | `openpyxl` 可写单元格批注，标注「此字段由 XXX 工具生成，勿手改」 |
| 单独一列标记 | 加 `#source` 列写 `manual` / `generated`，比颜色可靠（可筛选、可校验） |
| 保护工作表 | 锁定生成区，只解锁人工填写区 |

**推荐优先级**：文字标记 > 批注 > 颜色。因为文字能筛、能校验、打印不掉、色盲可读。

## 6. 配置表反模式（有官方支撑）

| 反模式 | 后果 |
|---|---|
| A1 不是 `##` 开头 | 整表被跳过导出 |
| 只建 xlsx 没在 `__tables__` 注册 | 数据不被收集 |
| 类型名汉化 | 类型报错 |
| 备注列漏 `#` | 进了游戏 |
| 行首 `##` 的注释行当成数据行改 | 怎么改都不生效 |
| 合并区列数 ≠ bean/容器占用列数 | 导出报错 |
| `list` 中间留空 | 元素错位 |
| datetime 留空 | 解析失败 |
| 主键重复 | 数据覆盖或报错 |
| 数值列用逗号分隔 | 误解析 |

## 7. 配置表反模式（无权威来源，属 UX 判断）

以下几项**找不到可靠的公开权威来源**把它们列为「配置表排版错误」，
但它们符合通用设计原则，可作为建议提出（要如实标注这是判断而非标准）：

- 列宽不统一（纯视觉，不影响导出）
- 混用全角半角符号（微软文档指出 DBCS 环境下重复值判断会把全角/半角视同 → 可能误判）
- 数字存成文本（Luban 的 `int` 填文字会类型报错，可间接支撑）
- 隐藏列藏着关键字段（Luban 按列位置读取，隐藏列**仍会被读取**——「隐藏≠删除」，
  这是「界面上看不到但确实生效」的隐蔽 bug 来源）
- 颜色无图例

---

## 8. 与其他模式的关键差异

| 维度 | config 模式 | report 模式 |
|---|---|---|
| 表头底色 | 不加（只加粗+下边框） | 加 `#F0F0F0` |
| 数字格式 | **不改**（可能掩盖真实精度） | 统一小数位 |
| 字体 | **不改**（尊重用户习惯） | 统一为雅黑 + Consolas |
| 斑马纹 | 不加 | 宽表才加 |
| 合并单元格 | 只报告，结构性合并保护 | 只报告 |
| 条件格式 | 加（重复主键标红、空值标黄） | 加 |
| 列宽/冻结/对齐/打印 | 都改（不影响导出） | 都改 |
