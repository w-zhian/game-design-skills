# 汇报表 / 看板专用规则

> 适用对象：给老板、同事、客户看的数据表。**第一原则：一眼看到重点。**
> 目标不是"信息全"，是"读者在 30 秒内知道该看什么"。

---

## 1. 信息层级：三层就够

| 层级 | 内容 | 视觉处理 |
|---|---|---|
| L1 结论 | 核心 KPI、同比/环比、一句话判断 | 最大字号（16-20pt）、加粗、放左上 |
| L2 支撑 | 分渠道/分区域/分产品明细 | 正文 11pt、常规 |
| L3 明细 | 逐笔流水、完整清单 | 9pt 灰色，或折叠、或放附录 sheet |

**rule of thumb**：读者视线走「Z」字（左上 → 右上 → 左下 → 右下）。
最重要的数字必须在左上象限，不要放在表格右下角。

---

## 2. 表格 vs 图表：先做这个选择

| 读者要什么 | 用表格 | 用图表 |
|---|---|---|
| 查精确值、排名、对比具体数字 | ✅ | ❌ |
| 看趋势、看异常、看分布 | ❌ | ✅ |

Stephen Few 的判据：**数据点少于约 20 个且需要精确读数 → 表格；看模式 → 图表。**
别用柱状图表达「A=1234 万，B=1235 万」这种差异 0.08% 的对比——图上看不出，表上一目了然。

（「≤20 个」这个数字是社区派生经验值，不是 Few 原文，权重放低。）

---

## 3. KPI 卡片区（看板顶部）

标准结构，四件套：

```
┌──────────────────┐
│ 标签（9pt 灰）     │   ← 这是什么
│ 数值（20pt 粗）    │   ← 是多少
│ ▲ 12.3% 同比      │   ← 变化（配箭头 + 颜色）
│ 对比基准说明       │   ← 跟谁比
└──────────────────┘
```

**关键规则**：
- 数值和单位：单位写在标签里（`销售额（万元）`），不要挤在数字后面
- 涨跌色：**中国市场默认红涨绿跌**（与欧美相反）。做游戏/国内业务数据必须用红涨绿跌。
- 变化必须带方向符号（▲▼ 或 +/-），不能只靠颜色
- 卡片数量 3-6 个。超过 6 个就没有「核心」了

## 4. 留白与分组

| 手段 | 数值 | 说明 |
|---|---|---|
| 区块间距 | 空 2-3 行 | 比加边框有效得多 |
| 列组间距 | 空 1 列，宽度设 2-3 | 视觉分组，比竖线干净 |
| 表格上/下留白 | ≥1 行 | 不要把表贴死在单元格边界上 |
| 行高 | 18pt 起 | 15pt 默认偏挤，汇报表要松一点 |

**格式塔原则的落地**：
- 邻近性**能压过**相似性 —— 靠近的两列会被认为是一组，哪怕颜色不同
- 共同区域（底色块）**能压过**邻近性 —— 画一个大底色块，比任何边框都能表达"这 5 列是一伙的"
- 所以：**先靠留白分组，不够再加底色，最后才加线**。顺序别反。

---

## 5. 高亮：克制到只剩一个

| 允许 | 禁止 |
|---|---|
| 高亮 1 个最需要关注的异常值 | 高亮所有"重要"的（= 都不重要） |
| 用加粗 + 底色双重编码 | 只用底色（打印黑白就丢了） |
| 用「数据条」表达量级差异 | 用彩虹色阶表达分类 |

**数据条（Data Bar）是汇报表的性价比之王**：在数字右对齐的列上加一条淡蓝数据条，
既保留精确值又传达量级，比三色刻度可靠得多（三色刻度的中间值含义模糊）。

**三色刻度的坑**：红-黄-绿的中间色没有任何语义，"黄"到底是好还是不好？
要么用两色（好/差），要么用数据条。

## 6. 数字的可读性

| 规则 | 做法 |
|---|---|
| 大数用万/亿 | `1,234,567` → `123.5 万`（中文读者友好，且规避千分位 locale 问题） |
| 精度匹配决策 | 汇报表不要 `1.0837`，要 `1.08`；精确值放明细 sheet |
| 同列同精度 | 一列里 `12` 和 `12.00` 混排是灾难 |
| 千分位 | 中文表慎用 `,`（德式 locale 下 `,` 是小数点，字面相同含义相反） |
| 百分比 | 统一 `0.0%`，不要 `12%` / `0.12` / `12.0%` 混用 |
| 负数 | 用 `-123` 或 `(123)`，全表统一一种 |

## 7. 投屏与打印（汇报表的真实使用场景）

### 7.1 投屏（会议室大屏）

| 问题 | 处理 |
|---|---|
| 对比度衰减 | 正文提到 `#000000`，弱化文字提到 `#525252`（不用 `#6F6F6F`） |
| 字号太小 | 正文最小 11pt，投屏版建议 12-14pt |
| 信息太密 | 投屏版应该是「精简版」，明细放附录 sheet |
| 缩放到 100% 再截屏 | 缩放 60% 时所有字号实际都变小 |

### 7.2 打印

| 设置 | 值 |
|---|---|
| 方向 | 宽表横向 |
| 缩放 | 1 页宽，`fitToPage=True` |
| 重复标题行 | 必设 |
| 页脚 | 页码 + 文件名 + sheet 名 + 导出时间 |
| 手动分页符 | 避免合计行/图表被切断 |
| 关键汇总 | 必须落在第 1 页 |

**黑白打印检查**：把表转灰度看一遍——所有靠颜色区分的信息是否还在？
若不在，说明颜色是唯一编码，必须补文字/符号。

## 8. 多 sheet 工作簿的导航

| 手段 | 做法 |
|---|---|
| 首页 | 第一个 sheet 做「目录页」，`HYPERLINK` 或 `Ctrl+K` 内部链接跳到各页 |
| 返回 | 每个子 sheet 左上角放「← 返回目录」链接，形成闭环 |
| 命名 | sheet 名带序号前缀（`01_总览`、`02_渠道明细`），排序稳定 |
| 颜色标签 | `sheet_properties.tabColor`，同组同色（配图例或说明页） |
| 数量 | 超过 15 个 sheet 必须有目录页 |

## 9. 汇报表反模式

| 反模式 | 为什么不行 |
|---|---|
| 所有格子都加边框 | 网格线噪音，读者抓不到重点 |
| 十几个 KPI 卡片 | 等于没有核心指标 |
| 红黄绿三色刻度刷满全表 | 中间色无语义，且全彩=全不重要 |
| 用合并单元格做标题 | 破坏引用、无法单独设格式、复制易错位 |
| 表头用 3 种以上字体/字号 | 视觉噪音，读者以为每列性质不同 |
| 数字全用 General 格式 | 小数位参差，无法对齐 |
| 备注列写在中间 | 打断数据列的连续性 |
| 导出时间不写 | 三个月后没人知道这份数据是哪个时点的 |

---

## 10. 一份汇报表的「完工检查」（10 秒扫一眼）

1. 左上角是否是我最想让老板看的那个数字？
2. 眯起眼睛看，能不能看出 2-3 个视觉焦点（而不是一片均匀的灰）？
3. 把表转成灰度，信息是否还完整？
4. 有没有哪个数字需要读者用计算器才能理解（比如未换算的 1234567）？
5. 表头是否需要记忆（缩写得让人猜）？
6. 每一列的小数位是否一致？
7. 有没有超过 3 种底色？
8. 打印预览第一页是否能看到核心结论？

八条全过 → 可以发了。
