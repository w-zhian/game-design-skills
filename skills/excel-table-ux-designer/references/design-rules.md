# 通用排版规则库

> 这一份是「不管什么表都能用」的底层规则。所有数值都有来源，见文末。
> 冲突项明确标出，不做和稀泥。

## 1. 配色：一套可直接用的数值

### 1.1 核心色板（light 主题，最常用）

| 角色 | HEX | 用在哪 | 实测对比度 |
|---|---|---|---|
| 表头底 | `#F0F0F0` | 表头填充（浅色方案） | 配 `#262626` 字 = 13.28:1 ✅AAA |
| 表头字 | `#262626` | 表头文字 | 13.28:1 ✅AAA |
| 表头底（深色方案） | `#393939` | 要让表头更抢眼时 | 配白字 = 11.55:1 ✅AAA |
| 表头字（深色方案） | `#FFFFFF` | — | 11.55:1 ✅AAA |
| 分隔线 | `#D9D9D9` | 表头下、合计行上 | 1.32:1（非文本，靠形状识别） |
| 次级分隔 | `#E0E0E0` | 列组之间的弱分隔 | — |
| 正文 | `#161616` | 数据文字 | 18.10:1 ✅AAA |
| 次要文字 | `#525252` | 备注、注释列 | 7.81:1 ✅AAA |
| 弱化文字 | `#6F6F6F` | 单位、脚注 | 5.02:1 ✅AA |
| 斑马纹 | `#F4F4F4` | 宽表隔行（仅 >20 列时用） | 配正文 16.45:1 |
| 强调 | `#0F62FE` | 链接、关键数 | 白底 5.00:1 ✅AA |
| 强调深阶 | `#0043CE` | 小字号蓝字（更稳） | 7.79:1 ✅AAA |
| 警示/错误 | `#DA1E28` | 错误状态 | 5.00:1 ✅AA |
| 成功/正常 | `#24A148` | 正常状态 | — |
| 警告 | `#F1C21B` | 警告状态（**必须配深色字**） | — |

来源：IBM Carbon（Gray/Blue/Red/Green/Yellow 官方色阶）、Ant Design（gray-3、default border）。
对比度按 W3C 公式实测：`L=0.2126R+0.7152G+0.0722B`（先线性化），`(亮+0.05)/(暗+0.05)`。

### 1.2 状态色（色盲安全）

红绿不分的人约占男性 8%、女性 0.5%，其中 3/4 属绿色盲类。
若必须用颜色表示状态，用 Okabe-Ito 色盲安全八色，并**必须配文字或符号**：

| 语义 | HEX | 备注 |
|---|---|---|
| 橙 | `#E69F00` | 警告 |
| 天蓝 | `#56B4E9` | 信息 |
| 蓝绿 | `#009E73` | 正常 |
| 黄 | `#F0E442` | 需配深字 |
| 蓝 | `#0072B2` | 主色 |
| 朱红 | `#D55E00` | 错误 |
| 紫红 | `#CC79A7` | 次要 |
| 黑 | `#000000` | 文字 |

### 1.3 颜色使用上限

- **静态填充 ≤ 3 种**：表头底 + 斑马纹 + 一个强调。超过 3 种颜色即失去语义。
- **颜色永远不做唯一编码**：标红必须同时有文字/符号，否则打印黑白或色盲用户直接丢失信息。
- **条件格式优于手工上色**：手工色是一次性快照，条件格式是常驻预警——数据变了颜色自己跟着变。

> ⚠️ **最重要的例外：有图例就不适用上限。**
> 如果表上写了「红=战略 / 黄=重点 / 绿=一般」，那颜色**就是信息载体**，不是装饰。
> 这时要做的不是删颜色，而是检查：图例写得清不清楚、放在读者第一眼能看到的位置没有、
> 是否同时有文字（分级列）做第二编码。
>
> 这个例外写进规则是踩过坑的：早期脚本只数颜色种类，看到 4 种就清空，
> 把用户的客户分级语义抹掉了。**颜色种类多 ≠ 颜色无意义。**

## 2. 对齐

| 内容类型 | 水平对齐 | 理由 |
|---|---|---|
| 数字 | **右对齐** | 位数不同也能上下位比较，小数点纵向对齐 |
| 文本 | **左对齐** | 左端固定，整列扫描时眼睛不用重新找起点 |
| 日期 | **左对齐** | 当作文本处理（除非要按时间排序，仍左对齐） |
| 短代码（≤4 字符） | 可居中 | 状态、等级、稀有度这类 |
| 表头 | **跟随该列数据的对齐方式** | 数字列表头也右对齐，读者的视线轴才对得上 |

**禁止**：数值列居中（P0 级问题）。居中让每一位数字悬空，无法比较大小。

**小数位对齐**：同一列小数位必须一致。`1.5` 和 `1.53846` 混排时，右对齐也救不回可读性——
必须靠 `number_format` 统一（金额 `#,##0`、系数 `0.00`、比率 `0.0%`）。

## 3. 边框与网格线

**默认不画竖线。** 这是 Few/Tschichold 体系的核心主张，眼动实验也支持：
竖线组错误率 10.7%，无网格线组 0%。

**保留的线（通常只要两条）**：
1. 表头下方一条（medium，`#D9D9D9`）
2. 合计/小计行上方一条（thin，`#D9D9D9`）

**全表四边框是反模式**：每格都被框住时，边框不再传递结构信息，退化等同于网格线，视觉噪音翻倍。
覆盖率 > 85% 时应当作「做了美化反而更难读」来报。

**例外**：列间距极窄（< 2 字符）导致串行时，可用极淡竖线；宽表（>25 列）可每 3-5 行加一条更淡的分隔线。

> ⚠️ **保留的冲突**：ReliefWeb 技术简报主张「每 3-5 条一条细线」，Few 体系主张「数据区内完全不画线」。
> 两家结论不同，取决于表的宽度和有无小计。**不要假装有唯一正确答案**——按表的实际形态选，并说明理由。

## 4. 斑马纹（隔行底色）

> ⚠️ **这是本规则库里争议最大的一项，三派结论相反。**

| 立场 | 主张 | 出处 |
|---|---|---|
| 支持（有条件） | 长表多列时用浅灰隔行防串行；少列时不必要甚至困惑 | Datawrapper |
| 反对（实用主义） | 除非表很宽，否则避免隔行填充 | Stephen Few |
| 强反对（Web 排版实践） | 隔行填充「通过高亮一半行来损害相邻行，扭曲了数据的含义」 | **Richard Rutter《Web Typography》**（⚠️ 初版误记为 Tschichold，2026-11-17 更正） |
| 中立 | 斑马纹是有效的 common region 手段，但边框/背景过度使用造成杂乱，优先用留白 | NN/g |

> 注意：Tschichold 只反对「表格被画成一张网」（分隔线问题），**没有专门谈过斑马纹**。
> 引文归属见 `research/01-table-design-theory.md` 冲突 3 的更正说明。

**落地判据**：
- 列数 < 20 → 不开（窄表加斑马纹增加困惑）
- 列数 ≥ 20 且行数 ≥ 30 → 开 `#F4F4F4`，这是真正的「防串行」场景
- 表里已有大量条件格式色 → 不开（会和状态色打架）

## 5. 字体与字号

### 5.1 字体选择

| 用途 | 推荐 | 理由 |
|---|---|---|
| 中文主体 | 微软雅黑 / 等线 | Windows 默认存在，不触发回退 |
| 数字列 | Consolas | 等宽（tabular figures），逐位对齐；含 lining figures |
| 避免 | 宋体做正文 | 笔画细，小字号在低分屏发虚 |
| 避免 | 混用 3 种以上 | 基线/字高不同，同一行内文字上下跳动 |

**字体回退是列宽跳动的元凶**：中文用 A 字体、英文用 B 字体时，
缺字回退会让同一列的字符宽度不一致，列宽看起来「自己会变」。统一字体栈可解。

### 5.2 字号分档

| 层级 | 字号 | 说明 |
|---|---|---|
| 表头 | 11pt 加粗 | — |
| 正文 | 11pt | Excel 官方默认 Calibri 11pt |
| 注释/脚注 | 9pt | 弱化，用 `#525252` |

**只用 3 档**。字号是层级信号，超过 3-4 档后层级过载，读者不再感知差异。

> ⚠️ **未验证**：「数字区 10pt、表头 11pt、注释 9pt」这类精确分档没有一手统一标准。
> 上表是「默认 11pt 起步 + 收敛到 3 档」的合理起点，当作**风格一致性建议**而非硬标准。

### 5.3 行高与列宽手感

| 项 | 值 | 说明 |
|---|---|---|
| 表头行高 | 22pt | 留呼吸空间 |
| 正文行高 | 18pt | 默认 15pt 偏挤；行高 ≈ 2× 字号较好 |
| 行高单位 | pt（1pt = 1/72 英寸，96DPI 下 ×1.3333 = px） | — |
| 列宽单位 | **字符数**（默认 8.43），非像素 | — |
| 列宽档位 | 只用 4 档 | 见下表 |

**列宽分档（4 档足够）**：

| 档 | 宽度 | 用于 |
|---|---|---|
| 窄 | 8 | ID、序号、等级、开关 |
| 中 | 14 | 名称、部门、短标签 |
| 宽 | 20 | 描述、分类路径 |
| 特宽 | 30-50 | 备注、说明、长文本 |

同类列必须同宽。出现 20 种宽度 = 没有规范。
列宽到像素没有与字体无关的定值（MDW 随字体变化），不要承诺「N 字符 = N 像素」。

## 6. 表头设计

三种方案，按场合选，**不要混用**：

| 方案 | 做法 | 适合 |
|---|---|---|
| A 浅底 | `#F0F0F0` 底 + `#262626` 加粗字 + 下边框 | 通用，最稳 |
| B 深底 | `#393939` 底 + 白字 + 加粗 | 汇报表要抢眼时 |
| C 极简 | 只加粗 + 下边框（medium） | 配置表、极简风、要打印的表 |

**表头文字**：
- 带单位写进表头（`销售额（元）`）而不是每格重复单位——省 100 次重复
- 表头可换行（`wrap_text`），但行高要相应加高
- 长表头用缩略 + 批注解释，不要把表头撑成 40 字符宽

**跨列标题**：用「跨列居中（Center Across Selection）」而不是合并单元格。
合并会破坏引用（只指向左上角格）、无法单独设置被合并格的格式、复制粘贴易错位。

## 7. 冻结窗格

| 表形态 | 冻结到 | 效果 |
|---|---|---|
| 行多（>40）列少 | `A2` | 冻结首行 |
| 行列都多（>40 行、>12 列） | `B2` | 冻结首行 + 首列 |
| 标记行在顶部 | `A{表头行+1}` | 冻结到人看的表头下一行 |

冻结语义是「交点右下角第一个单元格」。设 `B2` = 冻结第 1 行和第 1 列。
设错位置的表现是「冻结了但表头还是滚走了」，诊断器会报 `FREEZE_TOO_HIGH`。

## 8. 打印与投屏

| 设置 | 值 | 为什么 |
|---|---|---|
| 方向 | 宽表（>10 列）横向 | 纵向会把列压扁或截断 |
| 纸张 | A4（`paperSize=9`） | — |
| 缩放 | `fitToPage=True` + `fitToWidth=1` + `fitToHeight=0` | 按 1 页宽、不限高 |
| 重复标题行 | `print_title_rows = "$1:$1"` | 跨页后第 2 页起仍有表头 |
| 打印区域 | 明确指定 | 否则带出表外空白/备注栏 |
| 页脚 | `第 &P 页 / 共 &N 页` + `&F`（文件名）+ `&A`（sheet 名） | 打印件可追溯 |

**坑**：`fitToWidth` 与 `scale` 互相覆盖，谁生效取决于 `fitToPage` 开关。
要按页宽缩放就设 `fitToPage=True`，不要同时设 `scale`。

**投屏**：会议室投影对比度会衰减，投屏版把正文加深到 `#000000`、把弱化文字提到 `#525252`（不用 `#6F6F6F`）。

## 9. 中英混排的特殊问题

| 问题 | 表现 | 解法 |
|---|---|---|
| 字体回退 | 同一列中文和数字宽度不一致，列宽"自己会变" | 统一字体栈，数字用等宽 |
| 全角/半角混用 | `（` 与 `(`、`，` 与 `,` 混着打，DBCS 环境下重复值判断会把全角/半角视同，可能误判 | 统一用半角符号；中文标点只在正文里用 |
| 全角空格 | 看不出来但占两格 | 批量替换 `\u3000` |
| 中文列宽估算 | 1 个汉字 ≈ 2 个字符宽 | 列宽按 `中文×2 + 英文×1` 估 |
