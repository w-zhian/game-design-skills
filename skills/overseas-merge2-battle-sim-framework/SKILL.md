# 海外 Merge-2 × 战斗 × 模拟经营路由器

把 Merge 产物变成可选择的经营或战斗输入，让战斗检验玩家选择，并把结果写回下一轮 Merge、经营或世界。只读取当前问题匹配的模块；用共同合同表达 A/B/C，但不共享三条路线的所有权、压力、失败和回写结构。

## 工作流

1. **分类任务。** 判定市场/路线、产品循环、战斗形态、Merge 接口、单场遭遇、节奏/心流数值、竞品边界或验证任务。
2. **标注证据。** 使用 `[OBSERVED]` 表示直接观察，使用 `[INFERRED]` 表示由证据推导，使用 `[HYPOTHESIS]` 表示待项目数据验证。任何没有项目实测支持的精确数值必须标为 `[HYPOTHESIS]`，并说明将用什么数据替换。
3. **选择路线。** 明确 A/B/C 的核心所有权与主情绪；若均不适用，先定义新的所有权和主情绪。不得假设三条路线可换皮复用。
4. **加载模块。** 只读取匹配的 reference；跨模块问题先读定义输入/边界的模块，再读消费该输入/负责验证的模块，不默认全量加载。
5. **定义闭环。** 写清 `Merge → 经营 → 战斗 → 世界回写` 的输入、选择、可观察结果与下一轮影响。
6. **路由专业工作。** 需要具体战斗、数值、经济、循环、架构或 QA 规格时，显式交给对应专业 Skill；本 Skill 保留产品级取舍与跨系统合同。
7. **交付合同。** 选择下方最小充分模板，并通过质量门。

## A/B/C 所有权边界

| 路线 | 核心所有权与主情绪 | 压力来源 | 失败与回写 |
|---|---|---|---|
| **A 温馨庇护所** | 保护具体的人与空间；主情绪是安全与照护。 | 安全、照护与保护优先级。 | 主要回写伤员、设施临时受损、安全感与剧情选择；恢复必须明确、可控。 |
| **B 神话商旅** | 展示伙伴与器具组合；主情绪是结伴远行与发现。 | 组合、路线与临场协同。 | 主要回写伙伴状态、商队声望/机会或组合暴露；不得使用 A 的居民伤亡结构。 |
| **C 废土车队** | 检验装载、路线和连续损耗；主情绪是在匮乏中继续前进。 | 燃料、货物、车辆与风险取舍。 | 主要回写延误、载荷损失、耐久与后续路线；不得使用 A/B 的关系结构。 |

同一敌人进入三条路线时，也必须改变问题定义、玩家干预和结果回写：A 问“保护谁与哪里”，B 问“如何组合伙伴与器具”，C 问“牺牲什么载荷或路线继续前进”。只更换角色名、美术或数值不构成路线差异。

## 专业 Skill 路由

| 专业 Skill | 显式路由条件 |
|---|---|
| `combat-design` | 具体伤害、技能、敌人、Boss、战斗手感与可读性。 |
| `numerical-planning` | 公式、TTK、成长、概率、压力曲线与 Monte Carlo。 |
| `economy-design` | 资源流、失败成本、商业化压力与恢复。 |
| `gameplay-design` | 核心循环、内容节奏、活动消费与回流。 |
| `system-design` | 模块边界、状态写回与数据接口。 |
| `qa-review` | 跨模块一致性、P0/P1 与发布验收。 |

给专业 Skill 的输入应包含已选路线、证据标签、接口边界、首版范围和待验证问题；专业结果必须回到本 Skill 的产品闭环与质量门中复核。

## 输出合同

三个模板共享且只共享以下字段顺序：`判断 → 输入 → 阶段 → 干预 → 回写 → 代价 → 失效条件 → 验证`。字段长定义按任务读取对应 combat reference；模板本身只保留决策所需内容。

### 战斗概念卡

用于战斗形态或路线决策。

| 字段 | 必填内容 |
|---|---|
| 判断 | 一句话可删除性判断；同时写明本版不做什么。 |
| 输入 | 路线、核心所有权、主情绪、目标人群、阶段、证据与约束。 |
| 阶段 | 战前、战中、战后各自承担的产品职责。 |
| 干预 | 玩家最少一个战前选择，以及能造成可观察差异的战中或结算干预。 |
| 回写 | 结果改变 Merge、经营或世界中的哪些状态。 |
| 代价 | 制作、理解、内容、经济与情绪成本。 |
| 失效条件 | 哪种断链、换皮或用户反应会使概念应被删除或延期。 |
| 验证 | 最小原型、指标、护栏、样本窗口与 Kill Criteria。 |

### 单场遭遇规格

用于 `[HYPOTHESIS]` 45/60/75–90 秒原型；用项目实测完成时长分布替换该档位。

| 字段 | 必填内容 |
|---|---|
| 判断 | 这场遭遇检验哪个路线专属问题，以及玩家为何需要它。 |
| 输入 | 战前选择、Merge 产物、经营状态、敌人条件与可用情报。 |
| 阶段 | 按时间列阶段；每阶段写玩家问题、可观察因果和退出条件。 |
| 干预 | 每次干预的时机、选择、反馈、预期效果与副作用。 |
| 回写 | 成功、部分成功与失败分别写回哪些路线专属状态。 |
| 代价 | 时间、资源、损耗、恢复负担与内容生产成本。 |
| 失效条件 | 失败如何被玩家解释；若只能解释为总战力不足，规格失效。 |
| 验证 | 行为事件、分段漏斗、因果对照、访谈问题与 Kill Criteria。 |

### 战斗—Merge—经营接口审计

逐接口判定“行为变化 / 数值加成 / 断链”，并给出最小修复。

| 字段 | 必填内容 |
|---|---|
| 判断 | 逐接口标记行为变化、数值加成或断链，并给总体可删除性结论。 |
| 输入 | Merge 对象、经营状态、战斗状态及其来源、所有者与时效。 |
| 阶段 | 按 `Merge → 经营 → 战斗 → 世界` 列状态转移和消费时点。 |
| 干预 | 对每个断链给一个最小修复，并说明修复改变的玩家行为。 |
| 回写 | 战斗结果写回的对象、范围、恢复方式和下一轮可见反馈。 |
| 代价 | 新接口、状态同步、经济波动、教学与 QA 成本。 |
| 失效条件 | 只有百分比加成、单向消耗、不可见结果或路线所有权错配。 |
| 验证 | 接口日志、行为差异、经济护栏、断链复现与回归验收。 |

## 质量门

- 战斗不能只是观看总战力；至少存在一个战前选择，以及一个可观察的战中或结果差异。
- 合成物至少跨两个系统；战斗结果至少写回 Merge、经营或世界中的一个。
- 每项推荐同时说明旋钮、预期效果、副作用和验证指标。
- 每个精确项目值都标为 `[HYPOTHESIS]`，并说明将用哪项项目数据替换。
- 明确至少一个首版删除或延期项；不把完整 Gacha、实时 PvP、跨服、联盟压力等重系统默认塞入首版。
- A/B/C 的问题、压力、失败、恢复与回写符合各自所有权，不把同一设计换名复用。
- 事实、推断与假设就近标注；当前市场、竞品、平台、政策或价格必须重新核验，不能只依赖静态研究。
- 若任一箭头只能写“加战力”或“给金币”，判定闭环未成立并返回最小修复。

## 常见错误

- 为显得完整而读取全部 references：回到选择性研究路由，只加载能改变当前判断的模块。
- 把战斗失败写成通用扣血或角色死亡：按路线所有权重新定义压力、恢复与回写。
- 给出精确 TTK、留存或经济阈值却没有项目实测：标记 `[HYPOTHESIS]`，补充替换数据与验证窗口。
- 把专业细节堆入产品判断：路由到对应专业 Skill，再复核跨系统合同。
