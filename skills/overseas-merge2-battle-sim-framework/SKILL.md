# 海外二合战斗模拟经营 · 产品决策框架

> 二合创造可用资源，经营决定资源投向，战斗检验选择，结果必须改写下一轮二合与经营。

## 激活后的第一步

不要立刻罗列功能。先完成以下路由：

1. 判断用户是在做：
   - 新概念；
   - 核心循环；
   - Merge 物品链；
   - 战斗嵌入；
   - 经营/经济；
   - 商业化/LiveOps；
   - 买量素材；
   - MVP/软启动；
   - 三案立项比较；
   - 已有设计评审。
2. 判断最接近的产品路线：
   - **A Cozy-first**：照顾家与具体的人。
   - **B Collection-first**：培育伙伴并远行。
   - **C Logistics-first**：装载、选路和车队生存。
   - 若均不匹配，先写出新的“核心所有权”和“主情绪”，再使用母框架。
3. 输出一句可证伪的产品判断，而不是泛泛说“有潜力”。
4. 画出三环因果链，检查每一环如何改变下一环输入。
5. 给出最小验证方式和否决条件。

### 输入收敛与追问上限

先从用户输入和已有材料提取：

1. 任务阶段：概念、原型、软启动或线上产品。
2. 路线/核心所有权：A、B、C 或新候选。
3. 目标市场、平台与年龄定位。
4. 已有项目数据：CPI、留存、LTV、付费、素材与访谈。
5. 团队、预算、周期和内容产能。
6. 用户明确的必做项与禁区。

执行规则：

- 信息足够时不要追问，直接回答。
- 只有缺失信息会实质改变核心所有权、商业模式或是否引入 Gacha/PvP/4X，且无法安全假设时，最多提出 1 个阻断问题。
- 非阻断缺口不追问；最多列 3 条显式 **[待验证假设]** 后继续，并说明假设变化会怎样改变结论。
- 不凭空给 CPI、留存、LTV、产能或收入阈值；没有可靠基准时，给测量方法和阈值设定方式。
- 口径可比时，用户提供的项目一手数据优先于公开行业估算。
- 内部数据与公开来源冲突时保留矛盾，检查国家、平台、时间、净/毛收入、D2C 与样本口径，不擅自调和。
- 调研只覆盖可能改变当前决策的维度；可靠信息不足时停止扩搜并标记“待验证”，不使用弱来源凑数。

### 三个强制检查点

#### Checkpoint A：路线与输入边界

完整设计前，确认或显式假设目标市场/平台、核心人群/主情绪、团队/周期/产能、主要商业目标和不能做的重系统。

若信息不足但不改变路线，用假设继续；若会改变核心所有权或商业模式，遵守一次阻断问题上限。

#### Checkpoint B：Scope Gate

写完整规格前列出：

- 首发必须有。
- 证据成立后解锁。
- 明确不做。
- **为加入本设计而主动删除/延后的系统。**

若首发同时包含完整 Gacha、实时 PvP、跨服、联盟压力、独立活动经济中的两项以上，默认退回证据阶梯。

#### Checkpoint C：立项冻结

三案比较必须先冻结相同市场、平台、流量来源、版本完成度、预算、时间窗、指标和证据等级。未冻结时只能给“验证优先级”，不能声称已正式立项。

### 单功能变更评审快路径

当用户只是给已知路线增加、删除或修改一个功能，不展开完整新规格。直接回答：

1. **结论**：保留、修改后保留、延后解锁或删除。
2. **核心所有权影响**：它强化还是破坏 A/B/C 的主情绪？
3. **三环影响**：改变哪个输入，结果回写哪里？
4. **收益 / 代价 / 失效条件**。
5. **最小测试与 Kill Criteria**。

只有当该功能改变主情绪、核心所有权、主要循环或商业模式时，才升级为完整规格。

当用户坚持高风险方案时，不空泛迎合。输出：

1. 不建议作为主方案的原因。
2. 可隔离验证的最小版本。
3. 不得突破的护栏。
4. 触发即删除的 Kill Criteria。

## 回答工作流（Agentic Protocol）

**核心原则：涉及具体市场、竞品、政策、平台规则或近期数据时，先获取当前真实信息，再给判断。**

### Step 1：问题分类

| 类型 | 典型问题 | 行动 |
|---|---|---|
| 纯框架 | “战斗怎么和二合结合？” | 直接使用七模型分析 |
| 当前事实 | “2026 年海外 Merge 市场如何？” | 必须搜索最新可靠来源 |
| 具体竞品 | “对标 Gossip Harbor 是否合理？” | 先查官方产品和当前版本，再拆解 |
| 商业/政策 | “能不能做魔宠抽卡？” | 先查目标地区和商店当前政策 |
| 混合 | “这个概念在美国能否成立？” | 先研究受众/竞品事实，再用框架判断 |

### Step 2：框架式研究

需要事实时，从问题相关维度中选择，不做无边界竞品清单：

#### 市场与受众

- 品类收入、下载、时长与增长是何口径？
- 目标国家、平台、年龄和付费能力是否不同？
- 人口画像是官方数据、第三方估算还是待验证假设？
- 头部集中度和 UA 依赖意味着什么？

#### 产品结构

- 广告、商店页、首日与长期核心是否一致？
- Merge 对象是否真实进入经营或战斗？
- 经营选择是否改变规则，还是只加百分比？
- 战斗结果是否回写订单、路线、角色或库存？

#### 经济与商业化

- 常驻货币、行动资源与活动代币各有多少？
- 收入来自能量、事件、通行证、收藏、社交还是战力？
- 是否存在随机物品、儿童吸引力、真实价格和概率披露风险？

#### LiveOps 与产能

- 活动是否寄生于主行为，还是复制完整新经济？
- 一个主题能否跨棋盘、经营、战斗、剧情与商品复用？
- 团队需要持续生产哪些独占资产？

#### 证据等级

优先顺序：

1. 官方商店、开发商材料、平台和监管政策。
2. 数据持有方原始报告。
3. 可信行业拆解。
4. 用户评论，只作定性信号。
5. 推断，必须明确标注。

排除知乎、微信公众号、百度百科/百度知道。

### Step 3：三环分析

用以下格式在内部检查：

```text
Merge 输入/动作：
  ↓ 产出什么可用对象？
经营选择：
  ↓ 改变什么生产、岗位、空间或路线？
战斗/远征：
  ↓ 检验了哪个选择？
世界结果：
  ↓ 回写什么订单、资源、关系、伤势或情报？
下一轮 Merge：
```

若任一箭头只能写“获得金币/战力”，循环尚未融合。

### Step 4：输出

默认输出顺序：

1. **产品判断**：一句话。
2. **核心因果链**：30 秒、单次会话、日、周/赛季。
3. **关键设计**：只写能改变结果的系统。
4. **商业与内容代价**。
5. **风险与否决条件**。
6. **最小验证**。
7. **事实 / 推断 / 待验证假设**。

关键判断第一次出现时必须就近标注：

- **[事实]**：有可靠来源直接支持。
- **[推断]**：由事实通过框架推导。
- **[待验证假设]**：需要本项目用户、素材、留存、LTV 或产能数据确认。

文末可以汇总，但不能只在文末补标签。

## 七个核心心智模型

### 1. 三环齿轮，而非三层蛋糕

Merge、经营、战斗必须互相改变下一环输入。只把三套玩法放进三个按钮，会承担三份成本却没有融合。

应用：

- 新功能必须说明改变哪个系统输入。
- 单独体力、货币和战力系统默认需要删除或重接。

局限：

- 不要求所有对象同时跨三系统；首周只需一条极清楚的因果链。

### 2. 承诺守恒

产品复杂度可以增长，但广告、首日和长期核心不能替换玩家最初购买的心理契约。

应用：

- 规模化素材中的主要互动在前 10 分钟出现。
- D0—D7 可以自然重复。
- 不随中后期进度 sunset。

局限：

- 允许戏剧化、时间压缩和表现强化；守恒的是交互与因果。

### 3. 风险必须放大所有权

战斗的价值是让家、伙伴或车队更值得保护，而不是单纯增加惩罚。

应用：

- 失败生成修复、撤退、情报、关系或下一次选择。
- 不轻易永久摧毁情感和付费资产。

局限：

- 风险仍需带来机会成本、资源损耗、伤势或路线放弃，不能把所有失败自动变成奖励。

### 4. 约束产生经营

如果玩家最终能同时拥有全部最优解，经营就会退化成线性升级。

应用：

- 使用容量、岗位、时间、情报和库存制造排序。
- 提供预览、撤销、换单、拆解和补救。

局限：

- 约束过密会变成堵塞和付费墙。

### 5. 一份资产，多重语义

同一角色、设施、车辆、生态或灾害应跨玩法、叙事与商业化产生价值。

应用：

- 新对象至少服务两个系统。
- 一个赛季主题覆盖棋盘、场景、敌人、剧情和商品。

局限：

- 核心角色、Boss 和高潮仍需要独占内容，不能全部模板化。

### 6. LiveOps 是产品架构

主循环必须从第一天可承载事件，否则活动会复制棋盘、经济、UI 和团队。

应用：

- 一周一个主主题，三个系统共用奖励地图。
- [HYPOTHESIS] 可调起点：约 70% 参数/主题复用、20% 新内容、10% 新系统；必须用疲劳与收入数据校准。
- 最多三个常驻核心货币和两个同时可见活动代币。

局限：

- 模板比例必须由疲劳和收入数据校准。

### 7. 证据阶梯决定投资阶梯

市场增长不能证明自己的产品。每一层投资必须由上一层可证伪证据解锁。

顺序：

1. 真实素材概念。
2. 20—30 分钟闭环。
3. 7 日纵向切片。
4. 8—12 周经济与 LiveOps。
5. 重社交、完整角色池或世界战争。

局限：

- 短期指标可能低估需要情感累积的内容，应与访谈和内容产能共同判断。

## 十条决策启发式

1. **单系统对象删除测试**：只服务一个系统的物品，先删除或让它改变另一个系统输入。
2. **首周承诺测试**：广告主要操作不能在前 10 分钟出现并首周重复，就不规模化。
3. **胜负解释测试**：如果只能说“战力不足”，增加装载、站位、设施或路线决策。
4. **经营取舍测试**：如果设施最终都能同时满配，加入容量、岗位或维护成本。
5. **失败内容测试**：失败先生成修复、情报、关系或绕路，不先永久毁掉所有权。
6. **主题复用测试**：活动若同时要求新棋盘、新链、新角色、新敌人和新货币，默认缩减。
7. **核心人群优先**：A 保护照料感，B 保护伙伴身份，C 保护物流决策。
8. **深度后置测试**：完整 Gacha、实时 PvP、跨服与联盟压力由数据和组织能力解锁。
9. **透明付费测试**：付费卖效率、宽度、收藏和表现，不卖角色生命和基础入口。
10. **双周可生产测试**：无法按可持续周期继续生产的概念，不因原型好玩直接立项。

## 量化 Kill Criteria 模板

每个否决条件使用同一结构，避免“表现不好再优化”的无限拖延：

```markdown
假设：
目标人群/市场：
测试版本与流量来源：
主指标：
护栏指标：
比较基线：
样本或运行窗口：
通过阈值：
否决阈值：
未通过后的动作：删除 / 降级 / 重构 / 延后解锁
允许复测次数：默认 1 次，必须说明本轮改变了什么
```

“首周可重复”的可审计定义：

- 是同一类 **输入—选择—结果** 交互，不是只复用画面或奖励。
- 从首个会话可进入。
- D0—D7 至少在 4 个不同自然日有正常入口。
- 目标用户中位数在首周完成不少于 3 次；正式阈值需按会话频率校准。
- 该交互在长期产品中继续改变 Meta，而不是教学后失效。

## 重系统证据解锁表

| 重系统 | 最低解锁证据 | 未满足时 |
|---|---|---|
| 异步联盟 | D7 核心循环成立；玩家存在援助/共同目标动机；非付费成员有明确价值 | 保留好友援助与全服 PvE 目标 |
| 完整角色/伙伴 Gacha | 角色收藏动机、重复保护和付费意愿成立；年龄定位、概率、现实价格和保底合规完成 | 使用直接契约、任务获取、外观和通行证 |
| 实时 PvP | 战斗胜负可由决策解释；匹配、延迟、反作弊和客服能力通过压力测试 | 使用异步阵容、幽灵车队或规则挑战 |
| 同步世界 4X | PvE-first D30/LTV 成立；联盟参与健康；服务器生命周期、跨服、反作弊、24/7 运营预算获批 | 保留异步护送、共同 Boss 与赛季路线 |

## 三条产品路线

### A《Last Light Motel》

**主情绪：** 在危机中照顾具体的人。  
**核心所有权：** 旅馆、居民、关系。  
**Merge：** 食物、工具、药品、灯具、防务材料。  
**经营：** 房间、设施、居民岗位和四类订单。  
**战斗：** 每日一次 45—90 秒三入口自动防守，战前准备 + 两次轻干预。  
**结果回写：** 维修、营救、治疗、庆祝和人物冲突。  
**商业：** 剧情、装饰、活动、便利；不做英雄抽卡和付费救人。  
**否决：** 战斗不改善留存/素材质量，或 Cozy 核心持续感到被强迫考试。

### B《Mythic Caravan》

**主情绪：** 发现、培育并带伙伴远行。  
**核心所有权：** 伙伴、图鉴、移动商队。  
**Merge：** 食物、药剂、蛋胚、谱系记忆、符文和模块。  
**经营：** 五种商队模块受容量限制，改变生产与路线。  
**战斗：** 三宠自动执行、战前站位、一件器具、一次主动指令。  
**结果回写：** 生态钥匙、谱系、蓝图和新订单。  
**商业：** 直接伙伴契约、外观、生态通行证；首发不依赖完整角色池。  
**否决：** Merge/战斗用户无法交叉，或伙伴内容产能无法支撑承诺。

### C《Dustbound Convoy》

**主情绪：** 资源永远不够，但车队必须继续向前。  
**核心所有权：** 车辆、货物、幸存者。  
**Merge：** 武器、装甲、引擎、补给、医疗和侦察。  
**经营：** 车厢格、车辆岗位、幸存者职业和阵营关系。  
**战斗：** 自动追逐，玩家换道、标记目标、使用一次技能；路线连续 4—7 个节点。  
**结果回写：** 货损、伤员、绕路、维修、残骸和关系。  
**商业：** 成长、通行证、车辆外观、异步联盟；首发不做同步世界战。  
**否决：** PvE-first 无法形成 D7，或广告核心在真实游戏中被边缘化。

## 新路线准入门

不要因为换了题材就创建“路线 D”。新路线必须同时满足：

1. 有区别于家/伙伴/车队的核心所有权。
2. 有一句清晰且不可被 A/B/C 替代的主情绪。
3. Merge 对象、经营约束、风险检验和结果回写形成完整闭环。
4. 至少一个目标人群或使用场景与现有路线显著不同。
5. 内容和商业化结构不是简单复制现有路线。
6. 真实素材概念能表达该差异，并设置单独 Kill Criteria。

只更换海底、太空、农场或中世纪美术时，优先作为 A/B/C 的题材变体。

## 无战斗与灾害替代

灾害结算可以承担战斗的系统功能：检验准备、制造风险、产生结果回写。若玩家不与敌人对抗，产品仍可使用三环模型，但需要：

- 把“战斗”重命名为风险/灾害结算。
- 不继续沿用“战斗品类”的受众、收入和买量假设。
- 重新调研对应的 Survival Management、Time Management 或 Narrative Simulation 市场。
- 证明灾害不是纯数值扣除，而是有可观察的准备选择和世界后果。

## 儿童向随机孵化决策树

1. **纯免费随机，且无法付费加速：** 可以评估；仍需重复保护、年龄适配和清楚结果。
2. **免费随机，但体力、次数或加速可付费：** 视为与变现相关的随机机制；必须做年龄、平台、地区与真实价格审查。
3. **直接付费随机：** 对明显面向儿童的产品默认不做。任何例外都需要地区法律意见、平台合规、家长控制、概率披露、硬保底和伦理评审。

不能用“蛋是免费送的”规避玩家实际通过付费购买更多随机机会的事实。

## 核心张力

主题 Skill 不调和以下矛盾，而是根据路线和证据明确选择：

1. **低门槛 vs 长线深度**：越容易理解，越可能缺乏中期选择；越早堆叠系统，越可能破坏入口。
2. **安全感 vs 风险**：危险能放大所有权，过度惩罚也会摧毁 Cozy 与伙伴依恋。
3. **伙伴身份 vs Merge 消耗**：合并无人格物品是满足，合并已命名伙伴可能被视为损失。
4. **高付费上限 vs 用户信任**：能量墙、随机池和联盟压力可以变现，也最容易违背初始承诺。
5. **内容丰富 vs 生产可持续**：活动越多，永久运营负债越高。
6. **泛用户扩圈 vs 鲜明主情绪**：可以探索增量人群，但不能让 A/B/C 的核心所有权变模糊。
