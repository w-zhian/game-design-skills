# Merge-2 战斗 Skill：RED 基线测试 Prompt

## 运行边界

- 被测版本：当前 Skill 目录中的 v1 基线 `SKILL.md`。
- 本测试不使用项目实测数据、竞品精确阈值或任何未在 Prompt 中给出的事实。
- 评分：每个必需字段记为 `0=缺失`、`1=部分`、`2=完整`。任一字段为 0 即该 Prompt 不通过。
- 记录回答时，应保留能支撑评分的简短原始回答摘录；不要为了确认 RED 而补写被测 Skill 没有给出的结构。

## P1：A 路线 60 秒夜间防守

为温馨旅馆庇护所路线设计一场 60 秒局内防守，必须输出战前选择、时间分段、玩家干预、可观察因果、失败回写、验证指标；不得只写氛围和总战力。

| 必需字段 | 评分锚点 |
|---|---|
| 战前选择 | 明确至少一个会改变防守行为或结果的准备选择 |
| 时间分段 | 覆盖完整 60 秒，并给出可执行的阶段/时点 |
| 玩家干预 | 明确干预次数、时机和效果 |
| 可观察因果 | 把准备/干预与可见战局结果逐项连起来，不能只说“战力提升” |
| 失败回写 | 失败产生可继续处理的旅馆、居民或订单后果 |
| 验证指标 | 给出可测指标、观察窗口及通过/否决判据 |

## P2：武器链跨入战斗

定义一条 Merge-2 武器链如何进入战斗，必须输出合成物身份、战斗对象、触发时机、空间/目标差异、局后回写、降级为战力加成的判定；不得编造竞品公式。

| 必需字段 | 评分锚点 |
|---|---|
| 合成物身份 | 说明该物品在棋盘上的来源、层级或语义，不能只叫“武器” |
| 战斗对象 | 说明它进入战斗后实际作用于什么单位、位置或系统 |
| 触发时机 | 明确从 Merge/库存到战斗生效的节点 |
| 空间/目标差异 | 写出至少一项因空间、站位、目标类别而改变的效果或取舍 |
| 局后回写 | 战斗结果如何返回库存、订单、维修、路线或下一轮 Merge |
| 降级判定 | 可审计地说明何时它只是数值战力加成而不再是跨系统对象 |

## P3：B/C 同敌异构

让神话商旅和废土车队面对同一种敌人，必须输出两条路线各自的所有权、压力源、干预动作、失败结果、结果回写，以及不能共用的机制；不得只换皮。

| 必需字段 | 评分锚点 |
|---|---|
| B 所有权/压力/干预/失败/回写 | 五项分别可辨认，且围绕伙伴、图鉴或移动商队 |
| C 所有权/压力/干预/失败/回写 | 五项分别可辨认，且围绕车辆、货物或幸存者 |
| 不可共用机制 | 明确至少一组不能在两路间直接复用的规则，而非只列美术差异 |
| 非换皮因果 | 同一敌人下的选择、损失或回写能导向不同的后续循环 |

## P4：浪漫餐厅反例

判断浪漫餐厅与当前项目的品类关系，必须区分 Merge-2 剧情经营基准、是否有战斗、可借鉴层与不可类推层；不得把经营阻塞当战斗。

| 必需字段 | 评分锚点 |
|---|---|
| 品类关系 | 明确该案例是相邻基准、反例或不适用，并说明理由 |
| Merge-2 剧情经营基准 | 分开说明其可作为 Merge/订单/剧情经营的哪些基准 |
| 是否有战斗 | 直接判断是否存在对抗性战斗或风险结算，不能以忙碌/倒计时替代 |
| 可借鉴层 | 至少区分一项可迁移的结构性做法 |
| 不可类推层 | 至少区分一项不能迁移到战斗设计的结论，并说明边界 |

## P5：无项目数据的 TTK 曲线

在没有项目实测数据时提出局内 TTK/压力曲线，必须标注事实、推断、设计假设，输出归一化指标、阶段目标、替换实测的方法、Kill Criteria；不得伪造精确竞品阈值。

| 必需字段 | 评分锚点 |
|---|---|
| 证据标注 | 事实、推断、设计假设各自可定位，且不把假设写成事实 |
| 归一化指标 | 用可比较的无量纲口径定义 TTK/压力，包含分子、分母或基线 |
| 阶段目标 | 至少给出开局、中段、收束三个阶段的目标和曲线意图 |
| 替换实测的方法 | 明确原型/可用性/遥测的替代测量步骤及后续替换点 |
| Kill Criteria | 写明测试版本、主/护栏指标、窗口或样本、否决阈值与未通过动作 |
