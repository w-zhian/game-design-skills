# Merge-2 战斗形态谱系

> 职责：只回答“应该选哪一种战斗/风险结算形态”。接口合同见 `02-merge-combat-contract.md`，曲线与数值见 `03-flow-and-numerics.md`，遭遇内容见 `04-roles-enemies-encounters.md`。

## 证据与选型边界

- `[OBSERVED]` 本仓库母框架把 A 定义为“保护具体的人与空间”、B 定义为“展示伙伴与器具组合”、C 定义为“检验装载、路线与连续损耗”；三者共享“Merge 产物改变风险检验，结果回写下一轮”的合同。
- `[INFERRED]` 形态没有脱离产品所有权的通用排名。选型应先比较：玩家能否看懂准备选择、结果能否回写、同一内容能否复用、失败是否符合目标人群。
- `[HYPOTHESIS]` 首版只实现一项主形态加一种低成本结算变体；同时制作多套完整战斗只会在因果链尚未成立前放大内容、表现和数值成本。

## 六种形态

### 1. 据点防守

| 检查项 | 设计判断 |
|---|---|
| 战前选择 | `[HYPOTHESIS]` 选择主防区、岗位、设施状态与有限携带品；选择必须能在战场上定位到具体门、房间或对象。 |
| 战中输入 / 干预 | `[HYPOTHESIS]` 在可预告窗口调度照明、修复、诱饵或救治；避免持续微操。 |
| 胜负解释 | `[HYPOTHESIS]` 以“哪条防线为何失守、哪个准备如何生效”解释，不以总战力差代替。 |
| 结果回写 | `[HYPOTHESIS]` 生成维修、治疗、关系、设施停机、来客信任或新的 Merge 订单。 |
| 内容与制作成本 | `[INFERRED]` 固定场景和入口可复用，成本主要来自威胁词缀、目标状态、战损表现和归因反馈；低于持续移动的路线场景。 |
| 适用路线 | `[INFERRED]` A 强适配；B 可作为商队营地守夜；C 仅适合前哨或车队停驻，不宜替代移动路线。 |
| 失效 / 降级 | `[HYPOTHESIS]` 若玩家只会补最高耐久点、空间选择不改变敌人行为，降级为灾害结算或删除战中操作。 |

### 2. 轻阵容自动战斗

| 检查项 | 设计判断 |
|---|---|
| 战前选择 | `[HYPOTHESIS]` 编成、站位、目标优先级、器具与补给；至少有一项由主 Merge 棋盘直接产生。 |
| 战中输入 / 干预 | `[HYPOTHESIS]` 使用少量可保留的时机指令；自动执行负责降低操作负担，玩家负责判断。 |
| 胜负解释 | `[HYPOTHESIS]` 展示单位行为、站位受压、器具触发和关键目标处理；不能只展示稀有度或综合评分。 |
| 结果回写 | `[HYPOTHESIS]` 回写伙伴疲劳、器具耐久、生态情报、谱系材料、商队模块或新订单。 |
| 内容与制作成本 | `[INFERRED]` 阵容组合复用性高，但角色动画、技能可读性、AI 与平衡会持续产生高成本。 |
| 适用路线 | `[INFERRED]` B 强适配；A 可用居民岗位的极简版；C 可用车辆编队版，但不应抹去路线与货损。 |
| 失效 / 降级 | `[HYPOTHESIS]` 若换站位、器具或指令不改变可观察过程，降级为演出结算；若角色池吞掉 Merge，停止扩充角色养成。 |

### 3. 追逐 / 护送

| 检查项 | 设计判断 |
|---|---|
| 战前选择 | `[HYPOTHESIS]` 选择队形、载荷、护送目标、路线情报与应急资源。 |
| 战中输入 / 干预 | `[HYPOTHESIS]` 换道、标记目标、短时加速、抛弃诱饵或抢修；每次输入对应空间或时机。 |
| 胜负解释 | `[HYPOTHESIS]` 以目标存活、货损、距离、油料与车辆状态解释，不压缩成“敌军已消灭”。 |
| 结果回写 | `[HYPOTHESIS]` 回写货物缺口、伤员、残骸、绕路、阵营关系、车况与下一节点情报。 |
| 内容与制作成本 | `[INFERRED]` 需要移动场景、障碍、镜头、队形和目标 AI；表现和边界状态成本高于固定据点。 |
| 适用路线 | `[INFERRED]` C 强适配；B 可作生物护送；A 只适合少量营救高潮，不宜成为每日主形态。 |
| 失效 / 降级 | `[HYPOTHESIS]` 若换道只是躲红区、载荷不影响护送目标，降级为固定多入口防守；若目标 AI 不可控则先改为阶段结算。 |

### 4. 连续路线

| 检查项 | 设计判断 |
|---|---|
| 战前选择 | `[HYPOTHESIS]` 选择合同、部分可见路线、撤退条件、携带上限和维修策略。 |
| 战中输入 / 干预 | `[HYPOTHESIS]` 在节点间继续、绕行、维修、交易或撤退；单节点战斗沿用已验证的主形态。 |
| 胜负解释 | `[HYPOTHESIS]` 结算整段路线的净收益、累计损耗、错失机会和获得情报，而非只看最后一战。 |
| 结果回写 | `[HYPOTHESIS]` 回写库存、车况/疲劳、地图状态、阵营与生产优先级。 |
| 内容与制作成本 | `[INFERRED]` 除战斗外还需要路线图、事件池、跨节点状态、撤退与中断恢复，系统和 QA 成本高。 |
| 适用路线 | `[INFERRED]` C 强适配，B 中强适配；A 只适合章节级外出，不适合作为每日照料主轴。 |
| 失效 / 降级 | `[HYPOTHESIS]` 若玩家总选单位收益最高路线，或前节点不改变后节点，降级为单场合同；先修情报和机会成本，再扩节点。 |

### 5. Boss

| 检查项 | 设计判断 |
|---|---|
| 战前选择 | `[HYPOTHESIS]` 针对公开阶段机制选择克制物、保命资源、站位/路线和失败恢复。 |
| 战中输入 / 干预 | `[HYPOTHESIS]` 识别教导过的信号，在关键窗口打断、转火、抢修或保护目标。 |
| 胜负解释 | `[HYPOTHESIS]` 展示阶段机制处理、窗口使用、资源余量与失败点；不得把 Boss 只做成高 EHP。 |
| 结果回写 | `[HYPOTHESIS]` 改写章节世界状态、解锁蓝图/角色关系/新生产条件，并留下可复述的高潮。 |
| 内容与制作成本 | `[INFERRED]` 独占轮廓、动作、阶段、音画信号、剧情和大量边界测试使其成为高成本形态。 |
| 适用路线 | `[INFERRED]` A/B/C 都可用于章节高潮，但承担的所有权必须分别是家/伙伴/车队。 |
| 失效 / 降级 | `[HYPOTHESIS]` 若没有先行教学、独特决策或世界回写，降级为精英词缀；若靠数值墙制造高潮则停止扩制。 |

### 6. 灾害结算

| 检查项 | 设计判断 |
|---|---|
| 战前选择 | `[HYPOTHESIS]` 分配设施、人员、物资、保险/撤离和优先保护对象。 |
| 战中输入 / 干预 | `[HYPOTHESIS]` 可无实时输入，或只保留一次重分配；重点是逐步揭示因果，不是伪装成战斗。 |
| 胜负解释 | `[HYPOTHESIS]` 以服务中断、对象损失、资源消耗、恢复时间和被保护目标解释。 |
| 结果回写 | `[HYPOTHESIS]` 直接生成生产停机、修复链、关系、路线封闭、环境变化和新任务。 |
| 内容与制作成本 | `[INFERRED]` 复用经营场景和状态表现，AI/动画成本最低；但需要优秀的因果可视化，否则像后台扣数。 |
| 适用路线 | `[INFERRED]` A 强适配且可作为无战斗基线；C 可处理天气/故障；B 可处理生态灾害，但不能替代伙伴展示。 |
| 失效 / 降级 | `[HYPOTHESIS]` 若玩家看不到准备改变过程，只剩资源扣除，降级为叙事事件并停止称其为核心风险检验。 |

## A/B/C 路线适配

| 路线 | 首选 | 次选 | 后置 | 所有权护栏 |
|---|---|---|---|---|
| A Cozy-first | `[HYPOTHESIS]` 据点防守 | `[HYPOTHESIS]` 灾害结算 | `[HYPOTHESIS]` Boss、少量营救护送 | 结算必须点名被保护的人与空间；不得永久摧毁付费装修或把居民变成抽卡战力。 |
| B Collection-first | `[HYPOTHESIS]` 轻阵容自动战斗 | `[HYPOTHESIS]` 连续路线的简版 | `[HYPOTHESIS]` 生态 Boss、护送 | 结算必须展示伙伴与器具的行为贡献；不得让稀有度替代编成和 Merge 产物。 |
| C Logistics-first | `[HYPOTHESIS]` 追逐/护送 | `[HYPOTHESIS]` 连续路线 | `[HYPOTHESIS]` 车队 Boss、停驻防守 | 结算必须保留装载、路线、货损与连续损耗；不得退化成固定基地总战力。 |

## 选型顺序与最小可玩

1. `[HYPOTHESIS]` 先做“无战斗灾害结算”作为因果可读性的最低成本对照。
2. `[HYPOTHESIS]` 按路线只做一个主形态：A 据点防守、B 轻阵容自动战斗、C 追逐/护送。
3. `[HYPOTHESIS]` 主形态只验证一条 `准备选择 → 可观察变化 → 失败归因 → 世界回写 → 返回 Merge` 闭环；不同时验证角色池、完整经济与多活动。
4. `[HYPOTHESIS]` 只有主形态在“看懂、归因、决策、回流”四层通过后，才加 Boss 或连续路线。

### 最小可玩建议

- `[HYPOTHESIS]` 一个场景、一个主要目标、两种可互换准备、一个主动干预、一个明确失败点、两种世界回写。
- `[HYPOTHESIS]` 复用同一敌人/灾害，通过准备差异改变过程，不以新增敌人数量证明深度。
- `[HYPOTHESIS]` 战后必须允许玩家从结果卡直接回到对应 Merge 需求或经营修复入口。

## 降级与删除规则

- `[HYPOTHESIS]` **首版明确延期连续路线与独占 Boss**：二者分别引入跨节点状态和独占内容，必须由单场主形态证据解锁。
- `[HYPOTHESIS]` 若实时输入不能改变空间、时机或目标，删除实时输入，保留可解释结算。
- `[HYPOTHESIS]` 若准备项只提升统一百分比且无法在战场定位，按 `02-merge-combat-contract.md` 降级为普通数值加成。
- `[HYPOTHESIS]` 若战斗组相对无战斗基线没有改善归因或回流，且持续损害路线核心情绪，停止该形态，不以增加养成层补救。
