# Merge → 战斗接口合同

> 职责：只定义 Merge/经营与战斗之间可验收的数据与行为合同；不设计伤害公式、单位技能数值或资源价格。

## 目录

- 合同原则
- 通用对象合同
- 六类接口
- 战力加成降级判定
- 失败恢复与边界
- 验收清单

## 合同原则

- `[OBSERVED]` 母框架要求 Merge 创造可用资源、经营决定投向、战斗检验选择、结果改写下一轮。
- `[INFERRED]` 跨系统接口的价值不在“传了一个数”，而在玩家能否在配置、过程、解释或回写中辨认它改变了什么决定。
- `[HYPOTHESIS]` 每个首发接口至少绑定一个可观察行为变化和一个局后回写；只有 `power_bonus` 的对象不计核心接口。
- `[HYPOTHESIS]` 同一对象优先服务两种系统语义，避免为战斗另建棋盘、货币和养成黑箱。

## 通用对象合同

每个跨系统对象使用同一张设计卡；字段是语义合同，不是最终配置表。

| 字段 | 含义 | 验收问题 |
|---|---|---|
| `source_object` | Merge 产物、经营设施、岗位、路线情报或失败状态 | 玩家能否指出它来自哪里？ |
| `player_choice` | 玩家在出战前作出的选择 | 是否存在互斥项或机会成本？ |
| `combat_actor` | 被改变的单位、设施、目标、路径、资源或敌情 | 改变能否在战场定位？ |
| `behavior_delta` | 行为、空间、时机、目标或可用动作的变化 | 是新决定，还是相同决定的百分比放大？ |
| `feedback_cue` | 图标、轮廓、动画、音效、时间线或因果卡 | 玩家是否在第一次有效触发时得到反馈？ |
| `result_writeback` | 伤势、耐久、库存、关系、地图、订单、生产状态 | 战斗后是否产生下一步选择？ |
| `tuning_knobs` | 由专项 Skill 维护的可调参数名 | 能否调参而不改接口语义？ |
| `failure_signal` | 证明接口无效或破坏所有权的数据/访谈信号 | 什么情况下删除或降级？ |
| `owner_skill` | `combat-design`、`numerical-planning`、`economy-design` 等 | 谁负责精确公式与配表？ |

## 六类接口

### 1. 单位 / 设施

| 合同环节 | 内容 |
|---|---|
| Merge 输入 | `[HYPOTHESIS]` A：路障/照明/药品；B：伙伴谱系/商队模块；C：车辆模块/装甲/武器。 |
| 可观察战斗变化 | `[HYPOTHESIS]` 改变阻挡位置、攻击/支援行为、移动方式、目标保护关系或可用槽位；模型或场景状态同步出现。 |
| 结果回写 | `[HYPOTHESIS]` 耐久、伤势、疲劳、设施停机、车辆损伤或伙伴经历回到经营与 Merge 需求。 |
| 可调旋钮 | `[HYPOTHESIS]` 槽位、耐久消耗、作用范围、行为优先级、恢复条件；精确值路由至 `combat-design` / `numerical-planning`。 |
| 失败信号 | `[HYPOTHESIS]` 玩家只按最高阶放置；替换对象只改变综合战力；战场上无法指出谁/哪里发生变化。 |

### 2. 技能触发

| 合同环节 | 内容 |
|---|---|
| Merge 输入 | `[HYPOTHESIS]` 一次性器具、充能物、符文、医疗包、警报、EMP 或诱饵。 |
| 可观察战斗变化 | `[HYPOTHESIS]` 打开明确干预窗口，改变控制、揭露、转火、抢修、护盾或撤退时机；触发前可预览。 |
| 结果回写 | `[HYPOTHESIS]` 消耗、剩余充能、器具耐久、成功救援或错失窗口生成补给/维修/研究需求。 |
| 可调旋钮 | `[HYPOTHESIS]` 可用次数、窗口起止、前摇、目标规则、冷却、失败返还；具体战斗数值归 `combat-design`。 |
| 失败信号 | `[HYPOTHESIS]` 最佳时机永远是开场；自动释放与手动释放结果无差；玩家不知道为何能用或为何失效。 |

### 3. 站位 / 路线

| 合同环节 | 内容 |
|---|---|
| Merge 输入 | `[HYPOTHESIS]` 侦察物、路标、地图、车厢组件、设施布置、单位位置许可。 |
| 可观察战斗变化 | `[HYPOTHESIS]` 改变敌人接触顺序、保护对象、射界、通行、遭遇节点或撤退路径。 |
| 结果回写 | `[HYPOTHESIS]` 路线封闭/开放、设施占用、货物到达、角色暴露、地图情报与下一次布置成本。 |
| 可调旋钮 | `[HYPOTHESIS]` 槽位连通、情报可见度、重配成本、路径风险词缀、目标优先级；内容节奏归 `gameplay-design`。 |
| 失败信号 | `[HYPOTHESIS]` 所有场景存在同一最优站位；路线只是奖励倍率；移动不改变目标接触或资源损耗。 |

### 4. 战斗资源

| 合同环节 | 内容 |
|---|---|
| Merge 输入 | `[HYPOTHESIS]` 弹药、燃料、食物、药品、维修材料、照明能量或士气供给。 |
| 可观察战斗变化 | `[HYPOTHESIS]` 改变可持续时间、可用动作、撤退边界或连续节点选择；余量始终可读。 |
| 结果回写 | `[HYPOTHESIS]` 剩余量、短缺、废料、伤员与补给订单回到主经济；不凭空清零。 |
| 可调旋钮 | `[HYPOTHESIS]` 初始携带、消耗触发、保底动作、撤退返还、溢出转换；精确来源/消耗归 `economy-design`。 |
| 失败信号 | `[HYPOTHESIS]` 资源只相当于入场券；用尽后只能付费；玩家无法预估消耗；另一套战斗体力与主 Merge 能量平行存在。 |

### 5. 敌情 / 目标

| 合同环节 | 内容 |
|---|---|
| Merge 输入 | `[HYPOTHESIS]` 无线电、侦察无人机、足迹、居民情报、地图室或试战记录。 |
| 可观察战斗变化 | `[HYPOTHESIS]` 提前揭示压力类型、目标、阶段信号、弱点方向或路线代价，从而改变准备而非直接给伤害。 |
| 结果回写 | `[HYPOTHESIS]` 记录敌人行为、解锁克制链、更新地图/订单、提升后续预览质量。 |
| 可调旋钮 | `[HYPOTHESIS]` 信息层级、误差、揭示时机、可保留知识、失败后补充；遭遇机制归 `combat-design`。 |
| 失败信号 | `[HYPOTHESIS]` 情报不改变选择；弱点等同强制答案；信息只有文本没有战场信号；失败后仍无法解释。 |

### 6. 失败恢复

| 合同环节 | 内容 |
|---|---|
| Merge 输入 | `[HYPOTHESIS]` 维修、治疗、拖车、撤退路线、保险、备用设施或关系援助。 |
| 可观察战斗变化 | `[HYPOTHESIS]` 改变失败后的保留物、撤退时机、临时伤势或下一次入口，而非出售“立即胜利”。 |
| 结果回写 | `[HYPOTHESIS]` 明确记录损失、保留情报、修复任务、关系后果与再战可改项。 |
| 可调旋钮 | `[HYPOTHESIS]` 损失上限、恢复时间、保留比例、补救来源、重复失败保护；经济代价归 `economy-design`。 |
| 失败信号 | `[HYPOTHESIS]` 失败永久摧毁情感/付费资产；补救只有付费；失败自动变奖励而无机会成本；玩家重试时没有新决定。 |

## 战力加成降级判定

### 五门测试

对每个候选接口逐门回答。任何一门通过都必须有可观察证据；“策划表里不同”不算。

1. **战前配置门**：玩家能否选择携带、放置、取舍、路线或目标？
2. **战中行为门**：它是否改变单位/设施/敌人的行为，而非只改变数值结果？
3. **空间 / 时机门**：它是否创造位置、顺序、窗口、撤退或资源分配判断？
4. **胜负解释门**：结果卡能否点名它怎样帮助或拖累结果？
5. **局后回写门**：它是否产生下一轮 Merge、经营、关系、地图或恢复选择？

### 判定规则

- `[HYPOTHESIS]` **核心跨系统接口**：至少通过“战前配置门”，并在其余四门中通过至少一门；同时存在局后回写。
- `[HYPOTHESIS]` **辅助接口**：玩家可辨认反馈，但没有新的取舍或回写；可保留为成长/表现，不计三环融合证据。
- `[HYPOTHESIS]` **普通战力加成**：玩家无法在战前配置、战中行为/空间/时机、胜负解释或局后回写中辨认变化。即使来源于 Merge，也必须降级命名，不能计为核心接口。
- `[HYPOTHESIS]` **删除候选**：与另一加成同质、没有独立反馈、增加货币/养成负担且不改变决定。

### 反例

- `[HYPOTHESIS]` “高阶汤让全队攻击提高”但无视觉、无配置、无结算归因：普通战力加成。
- `[HYPOTHESIS]` “高阶汤占用一个携带位，允许队伍在疲劳后继续下一个节点，结束后生成食材短缺”：核心接口。
- `[HYPOTHESIS]` “路障等级提高基地耐久”：普通战力加成。
- `[HYPOTHESIS]` “路障只能装在一处入口，改变冲刺敌人的接触顺序，损坏后生成维修链”：核心接口。

## 失败恢复与边界

- `[HYPOTHESIS]` A 的恢复优先落在人、房间、设施和关系；不得售卖居民存活权。
- `[HYPOTHESIS]` B 的恢复优先落在疲劳、撤退、器具消耗和保留生态情报；不得吞并已人格化伙伴。
- `[HYPOTHESIS]` C 的恢复优先落在货损、车况、伤员、绕路和拖车；不得让一次失败清空长期车队。
- `[HYPOTHESIS]` 零资源时仍保留一个低效但可操作的撤退/恢复路径；无限资源也不能消除站位、路线和目标判断。

## 验收清单

- [ ] 每个对象有明确 `source_object`、`player_choice`、`behavior_delta` 和 `result_writeback`。
- [ ] 玩家能在战场定位变化，而不是只看到战力数字。
- [ ] 结果卡能把胜负关联回准备项和可改项。
- [ ] 主棋盘物品没有被另一套战斗货币替代。
- [ ] A/B/C 使用同一合同字段，但回写各自核心所有权。
- [ ] 伤害、EHP、掉落、消耗和价格的精确公式已路由到对应专项 Skill。
- [ ] 未通过五门测试的对象已标为辅助加成或删除候选。
